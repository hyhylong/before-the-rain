# 演示录屏

最终演示文件：`demo.mp4`，**4 分 35 秒**，1280×800，H.264 + AAC，约 16.5 MB，已采用细化后的新版人物。生成命令为 `npm run demo:record`，需要本地服务已启动、Playwright Chromium 与 ffmpeg。

录制的是实际运行的浏览器界面：中文开场、多轮文字互动、角色表情与动作、带旁白和同步字幕的剧情片段、对话触发的灯塔照片、说话中点击停止并输入新话题、当前场景留影、会话诊断、断线演练及重试、最后雨停的环境变化。

Playwright 的原生视频不录制系统声音，因此脚本记录本地 MP3 与剧情视频音轨的实际 `playing/pause/ended` 时间、播放位置与音量，先合成 PCM，再用 ffmpeg 合入录屏。被打断的声音按实际停止位置截断，不补回未播放台词。当前成片包含 25 段实际播放的音频；没有录制麦克风，也不冒充真实人声输入。

原始浏览器录制为 374.24 秒，为符合题目的 3–5 分钟要求，画面与声音统一约 1.361 倍速，音高保持不变，输出 275 秒。未删除失败状态或伪造界面。时间点记录在 `demo-timeline.json`，均已转换为成片时间；记录的是发起操作的时间，实际画面会包含输入和加载等待。

若只有导出失败，录制元数据会保存在 `raw/recording.json`；可执行 `node scripts/mux-demo.mjs` 恢复导出，无须重新录制。`raw` 为生成中间文件，不放入源码包。

麦克风的真实设备识别留待人工验收。自动化测试额外使用明确的 SpeechRecognition 替身验证“说话 → 点击麦克风停止旧语音 → 倾听 → 新识别结果”的生命周期，以及旧识别回调的失效。
